## Executive summary

The site is in good technical shape: clean canonicals, reasonable schema (RealEstateAgent, Person, Article, FAQPage, BreadcrumbList), Vercel static delivery, sitemap, and robots.txt. The base is stronger than 80% of SG agent sites.

The opportunity is in five buckets, in this order:
1. **Sitemap hygiene + indexable junk** — `/blog/*` is orphaned from sitemap; `/index`, `/audit-sample`, `/testimonials-carousel`, `/tools-promo` should not be indexable.
2. **Duplicate calculator pages** — root-level (`/absd-calculator.html`) AND `/tools/absd` exist. Pick one canonical, 301 the other.
3. **Local-SG long-tail expansion** — district and town pages exist but rarely contain MRT-walking-distance specifics, school 1km/2km catchment lists, or new-launch-PSF tables. This is where SG buyers actually search.
4. **E-E-A-T depth** — CEA license is in schema, but no dedicated author bio page, no transaction list with verifiable detail, no media mentions.
5. **Internal linking** — insights → tools → contact is loose. The blog/insights split is structurally confusing for crawlers and humans.

Estimated effort to ship all HIGH-priority items: 8–12 hours of focused work.

## Snapshot of current state

**Strengths**
- Canonical tags present site-wide
- RealEstateAgent + Person + WebSite JSON-LD on home (well-formed, includes CEA R073319H as PropertyValue)
- FAQPage schema on `/faq` with 17 Q&As
- Article + BreadcrumbList schema on insights, district, HDB town, and launch brief pages
- 28 district pages (D1–D28) + 26 HDB town pages = strong long-tail surface area
- 33 launch briefs covering 2026/2027 GLS pipeline
- 29 insights articles (a real content moat)
- Hero image has descriptive alt text, width/height attributes, fetchpriority set correctly
- Vercel Analytics installed
- robots.txt blocks tracking parameters from being indexed as duplicates

**Weaknesses**
- 4 blog pages at `/blog/*` (absd-decoupling, absd-second-property, hdb-bto-vs-resale, hdb-upgrade-timeline) are NOT in sitemap.xml → not crawled
- 5 stale root-level calculator pages duplicate `/tools/*` routes → duplicate content / split link equity
- Sitemap includes pages that should be noindexed: `/index`, `/testimonials-carousel`, `/tools-promo`, `/audit-sample`, `/thank-you`
- Page titles widely use literal `--` (em-dash placeholder) instead of em-dash `—` or pipe `|` separator → looks like a templating bug to humans and Google
- HDB town pages (e.g. Punggol) have no school catchment content, no MRT-walk-distance tables, no notable BTO/SBF projects → thin for the keyword
- District pages have no detailed MRT proximity by project, no nearby primary school 1km list
- No dedicated author/about page schema beyond home
- `/listings.html` has no Product or RealEstateListing schema for active listings
- No HowTo schema on calculator pages (calculators are HowTo-eligible per Google)
- No Service schema on `/services.html`
- No Organization or LocalBusiness schema separate from RealEstateAgent (limits Knowledge Panel eligibility)
- og-image is one generic 1200×630 file used for every page — no per-article social cards
- 33 launch briefs reference projects with no Place/Residence schema, missing developer, address, lat/lng
- No `/launches` index page in sitemap (only individual briefs)
- No HTML sitemap page for human navigation (good for crawl too)
- No XML news sitemap or RSS feed for insights (limits Google Discover, GNews surfaces)
